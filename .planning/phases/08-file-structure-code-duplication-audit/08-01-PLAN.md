Systematically analyze lib/ directory structure and file organization:

1. **Directory Hierarchy Analysis:**
   - Review lib/ top-level directories (auth/, backend/, core/, models/, providers/, services/, main_function/, profile/, chat_group/, etc.)
   - Check for:
     * Inconsistent nesting depths (some features 2-deep, others 3-deep)
     * Unclear directory purposes (ambiguous names like "components" vs "core/widgets")
     * Feature directories missing standard subdirectories (components/, models/)
     * Orphaned directories with no clear parent feature
   - Use: `find lib -type d -maxdepth 3` and analyze patterns

2. **Module Boundary Violations:**
   - Identify files that don't belong in their current directory
   - Check for:
     * Widgets in services/ or models/ (UI in wrong layer)
     * Service logic in widget files (business logic in UI)
     * Models in backend/schema/ that should be in models/ (domain vs data layer confusion)
     * Utils scattered across features instead of lib/utils/
   - Look for imports crossing unexpected boundaries (e.g., chat_group importing from profile)

3. **Feature Organization Consistency:**
   - Compare organization across similar features:
     * main_function/ subdirectories (games_list/, golfers/, community/, etc.)
     * profile/ subdirectories (edit_profile/, main_profile/, etc.)
     * chat_group/ subdirectories
   - Identify inconsistent patterns (some have components/, some don't)

4. **Naming Pattern Issues:**
   - Scan all .dart files and check against conventions
   - Find files NOT following patterns:
     * Widgets without _widget.dart suffix
     * Services without _service.dart suffix
     * Inconsistent capitalization or spelling
   - Use: `find lib -name "*.dart" -type f` and regex matching

For each issue found, document:
- **Category**: "Misplaced File", "Unclear Module Boundary", "Inconsistent Organization", "Naming Violation"
- **File/Directory**: Full path from lib/
- **Line Numbers**: N/A (structural issue)
- **Explanation**: What's wrong and why it matters
- **Refactoring Suggestion**: Specific move/rename action with example
- **Priority**: Critical/High/Medium/Low based on impact
