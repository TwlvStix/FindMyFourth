**Audit Context:**
- 170 Dart files, many created through rapid feature development
- v1.0 achievements: 30+ reusable components created, 2,293 lines removed through refactoring
- Known from v1.0 audits: Premium card pattern duplicated 30+ times, list item pattern repeated 50+ times (many addressed)
- Focus areas: Widgets (especially form builders, card layouts), Services (query patterns), Providers (cache management)
- Target: Find remaining duplication after v1.0 component standardization

**Context from Prior Work:**
- Phase 2: Created AppCard, AppTextField, AppBadge to reduce duplication
- Phase 6: Extracted components from large widgets (game detail, create game, chat, golfers)
- These efforts addressed SOME duplication - audit finds what remains

**Anti-patterns to Look For:**
- Similar _build*() helper methods across widgets
- Repeated Firestore query patterns across services
- Duplicate form validation logic
- Copy-pasted UI layouts (especially premium/card styling)
- Similar StreamBuilder/FutureBuilder patterns
- Repeated error handling code
</context>

  <files>.planning/phases/08-file-structure-code-duplication-audit/DUPLICATION-AUDIT.md</files>
  <action>
Systematically search for code duplication in UI layer:

1. **Duplicate Helper Methods:**
   - Search for common method names across widget files:
     * `grep -r "_build" lib/main_function lib/profile lib/chat_group --include="*_widget.dart" | cut -d: -f2 | sort | uniq -c | sort -rn`
     * Identify methods with similar signatures appearing in 3+ files
     * Focus on: _buildHeader(), _buildCard(), _buildList(), _buildForm(), _buildAvatar()
   - Compare implementations to find near-identical code (80%+ similar)
   - Note: Some duplication is acceptable if logic is feature-specific

2. **Duplicate UI Patterns:**
   - Search for repeated widget trees:
     * Container + BoxDecoration + child patterns (gradient backgrounds, borders)
     * Row/Column layouts with identical padding/spacing
     * Card-like widgets with shadow + border radius
     * List tile patterns (avatar + title + subtitle + trailing)
   - Use grep for visual markers:
     * `grep -r "BoxDecoration" lib --include="*.dart" -A 5`
     * `grep -r "LinearGradient" lib --include="*.dart"`
     * Look for hardcoded colors/spacing that should use design tokens
   - Compare against existing components (AppCard, AppListTile, AppTextField) to find missed opportunities

3. **Form Validation Duplication:**
   - Search for duplicate validators:
     * `grep -r "TextFormField\|validator:" lib --include="*_widget.dart" -B 2 -A 5`
     * Identify repeated validation logic (email, password, phone, required fields)
   - Check if validation could be extracted to reusable validators

4. **State Management Patterns:**
   - Find repeated setState() patterns, especially:
     * Loading state management (isLoading, isSubmitting flags)
     * Error state handling (error messages, SnackBar displays)
     * Form state management (controllers, focus nodes)
   - Identify opportunities for custom hooks or state abstractions

5. **StreamBuilder/FutureBuilder Patterns:**
   - Search for repeated stream/future handling:
     * `grep -r "StreamBuilder\|FutureBuilder" lib --include="*.dart"`
     * Check for duplicate loading/error/empty state handling
     * Identify patterns that could use a wrapper widget

For each duplicate pattern found, document:
- **Pattern Name**: Short descriptor (e.g., "Premium Card Layout", "Email Validator")
- **Instances**: File paths and line numbers (at least 3+ instances to be considered duplication)
- **Code Sample**: Representative example showing the duplicate code (5-10 lines)
- **Explanation**: Why this is problematic (maintenance burden, consistency risk)
- **Refactoring Suggestion**: Specific extraction approach
  - Option A: Extract to reusable component/widget
  - Option B: Extract to utility function
  - Option C: Use existing component (if one exists)
- **Estimated Impact**: Lines of code saved, files affected
- **Priority**: Critical (10+ instances), High (5-9), Medium (3-4), Low (2)

Start generating DUPLICATION-AUDIT.md with widget duplication findings.
