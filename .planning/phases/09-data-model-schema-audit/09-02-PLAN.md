<task type="auto">
  <name>Task 2: Audit Firestore index configuration and usage</name>
  <files>.planning/phases/09-data-model-schema-audit/QUERY-PERFORMANCE-AUDIT.md</files>
  <action>
    **Analyze firebase/firestore.indexes.json:**

    **Current indexes (5 composite, 1 field override):**
    1. `games`: `isCancelled` (ASC) + `joined_players` (ARRAY_CONTAINS)
    2. `games`: `joined_players` (ARRAY_CONTAINS) + `isCancelled` (ASC) + `date` (ASC)
    3. `chats`: `users` (ARRAY_CONTAINS) + `last_message_time` (DESC)
    4. `chat_messages`: `chat` (ASC) + `timestamp` (DESC)
    5. `chats`: `memberIds` (ARRAY_CONTAINS) + `lastMessageAt` (DESC) + `__name__` (DESC)
    6. `fcm_tokens.fcm_token`: Collection group index

    **For each index, verify:**
    1. **Is it used?**
       - Grep codebase for queries matching this index
       - Check if any queries would trigger "index required" error without it
       - Identify unused indexes (technical debt)

    2. **Is it optimal?**
       - Field order matches query patterns (filters before sorts)
       - Ascending vs descending matches query direction
       - Array-contains is first filter (Firestore requirement)

    3. **Is it complete?**
       - All fields in query's where + orderBy clauses covered
       - Missing indexes that cause fallback to less efficient query patterns

    **Identify missing indexes:**
    1. **Games queries needing indexes**:
       - Friend games filtered by `friend_game` + sorted by `date`
       - Active games filtered by `status='active'` + sorted by `date`
       - User's hosted games: `uid` (equality) + `date` (sort)
       - Course games: `courseRef` (equality) + `date` (sort)

    2. **User queries needing indexes**:
       - Friends list: `friends` array-contains + any filtering?
       - Online users: `last_active_time` > threshold + sorting?

    3. **Chat queries needing indexes**:
       - Game chats: `type='game'` + `gameId` equality + `lastMessageAt` sort
       - Unread chats: `unreadCountByUser.{uid}` > 0 + `lastMessageAt` sort (may not be indexable)

    4. **Notification queries needing indexes**:
       - User notifications sorted by timestamp with read status filtering

    **Check for index anti-patterns:**
    - Duplicate indexes (chat_messages index #4 may be redundant with subcollection auto-index)
    - Over-specific indexes (index for query that's never executed)
    - Missing collection group indexes for subcollection queries
    - Unused fieldOverrides

    **Document with:**
    - Index ID (Q-INDEX-001, Q-INDEX-002...)
    - Collection and fields
    - Used by which queries (file paths)
    - Recommendation (add, remove, modify, keep)
    - Query error risk if removed (Critical if missing)
    - Priority and effort estimate
