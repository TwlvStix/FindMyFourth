  <files>.planning/phases/10-state-management-error-handling-audit/PROVIDER-PATTERNS-AUDIT.md</files>
  <action>
    Analyze widget-level state management for anti-patterns:

    1. **StatefulWidget Usage Audit:**
       - Search all StatefulWidget implementations (grep "extends StatefulWidget")
       - For each widget, determine if state should be in Provider instead
       - Identify widgets managing global state locally (anti-pattern)
       - Check for proper State lifecycle (initState, dispose, didUpdateWidget)

    2. **StreamBuilder/FutureBuilder Patterns:**
       - Audit all 44 StreamBuilder/FutureBuilder instances found
       - Check for missing error handling (builder should handle snapshot.hasError)
       - Verify loading state handling (snapshot.connectionState checks)
       - Identify duplicate stream subscriptions that should use Provider cache
       - Check stream subscription disposal

    3. **Local vs Global State Boundaries:**
       - Identify state hoisted too high (in Provider when should be local)
       - Identify state too low (in widget when should be in Provider)
       - Document state ownership confusion (game state, user state, UI state)

    4. **Context Usage Patterns:**
       - Audit context.watch() vs context.read() usage
       - Identify widgets rebuilding unnecessarily due to watch() on entire provider
       - Check for context.read() in build methods (anti-pattern - should use watch)
       - Verify Provider.of usage follows best practices

    Append findings to PROVIDER-PATTERNS-AUDIT.md under "Widget State Management" section.
