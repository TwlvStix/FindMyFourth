  <name>Task 1: Audit async patterns and race conditions</name>
  <files>.planning/phases/10-state-management-error-handling-audit/ASYNC-EDGE-CASES-AUDIT.md</files>
  <action>
    Analyze asynchronous operation patterns for bugs and anti-patterns:

    1. **Async/Await Usage Patterns:**
       - Search for await calls (grep "await\s+")
       - Identify awaits inside loops (potential performance issue or race condition)
       - Check for missing await on async calls (futures not awaited = fire-and-forget bugs)
       - Verify async functions return Future&lt;T&gt; not void
       - Identify async callbacks where sync expected (event handlers, builders)

    2. **Race Condition Analysis:**
       - Identify concurrent setState/notifyListeners calls
       - Check for multiple async operations modifying same state without coordination
       - Search for await Future.wait usage (proper) vs sequential awaits (inefficient)
       - Verify cache invalidation doesn't race with cache reads
       - Identify time-of-check vs time-of-use bugs (checking state then acting on stale value)

    3. **Stream Subscription Management:**
       - Audit all stream subscriptions for proper cleanup
       - Check StreamSubscription.cancel() called in dispose()
       - Identify missing listen error handlers (onError parameter)
       - Verify stream controllers are closed (StreamController.close())
       - Search for duplicate stream subscriptions to same source

    4. **Future Chaining and Error Handling:**
       - Check .then() vs async/await consistency
       - Identify .catchError() vs try-catch patterns
       - Verify .whenComplete() or finally cleanup
       - Search for unawaited futures (analyzer warnings)
       - Check Future.timeout() usage for long operations

    5. **Firestore Transaction Safety:**
       - Audit writeBatch and transaction usage
       - Verify transactional operations are truly atomic
       - Check for transaction retries on contention
       - Identify missing rollback handling
       - Search for runTransaction error handling

    6. **Issue Categorization:**
       Document each issue with:
       - File path and line numbers
       - Race condition description or async anti-pattern
       - Impact (data corruption, memory leaks, crashes)
       - Refactoring recommendation
       - Priority (Critical/High/Medium/Low)
       - Estimated effort (hours)

    **Categories:**
    - A-ASYNC-001 through A-ASYNC-999: Async/await anti-patterns
    - A-RACE-001 through A-RACE-999: Race conditions
    - A-STREAM-001 through A-STREAM-999: Stream management issues
    - A-TRANS-001 through A-TRANS-999: Transaction safety problems

    Generate ASYNC-EDGE-CASES-AUDIT.md with:
    - Executive summary with async safety health score (0-100)
    - Issue count by category and priority
    - Detailed issue list with code examples and fixes
    - Async best practices guide

<task type="auto">
  <name>Task 2: Audit edge case handling and defensive programming</name>
  <files>.planning/phases/10-state-management-error-handling-audit/ASYNC-EDGE-CASES-AUDIT.md</files>
  <action>
    Analyze edge case handling and input validation:

    1. **Null Safety Audit:**
       - Search for null checks before usage (widget?.method vs widget.method)
       - Identify missing null coalescing (?? operators)
       - Check for null assertion operators (!) that could crash (anti-pattern)
       - Verify nullable types properly handled in null-safe Dart
       - Search for late variable usage (delayed initialization risks)

    2. **Empty Collection Handling:**
       - Identify list.first/last without isEmpty checks
       - Search for map[key] without containsKey checks
       - Check for empty string handling ("" vs null)
       - Verify list access with index bounds checks
       - Identify filter/where operations that could return empty

    3. **Boundary Conditions:**
       - Check numeric operations for division by zero
       - Verify date/time operations handle edge dates (year boundaries, DST)
       - Identify string operations without length checks
       - Search for array access without bounds validation
       - Check pagination logic for first/last page edge cases

    4. **Input Validation Gaps:**
       - Audit form validators for completeness
       - Check for email/phone format validation
       - Verify password strength requirements
       - Identify missing required field validation
       - Search for numeric range validation (min/max)

    5. **Offline/Network Failure Handling:**
       - Search for connectivity checks before Firebase calls
       - Identify missing timeout handling for network operations
       - Check for offline data persistence strategies
       - Verify retry logic exists for transient failures
       - Identify operations that fail silently without network

    6. **State Machine Edge Cases:**
       - Check loading/success/error state transitions are complete
       - Identify states that can get stuck (no transition out)
       - Verify initialization sequences handle partial failures
       - Search for missing default cases in switch statements
       - Check for impossible states that should have guards

    Append findings to ASYNC-EDGE-CASES-AUDIT.md under "Edge Case Handling" section.
