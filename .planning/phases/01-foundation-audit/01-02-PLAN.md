# Plan 01-02: Document inconsistencies across key screens

**Goal**: Systematically identify and document UI inconsistencies across the app's key screens, focusing on spacing, typography, component usage, and visual patterns.

**Context**: With 136 Dart files and 7 large widgets (1300-2183 lines), inconsistencies are expected. This audit will catalog specific examples of inconsistent spacing, typography, button styles, card layouts, and other UI elements across feature areas.

**Success criteria**:
- Documented inconsistencies in spacing/layout across screens
- Documented inconsistencies in typography usage
- Documented inconsistencies in component styling (buttons, cards, inputs)
- Specific examples with file locations for each inconsistency type
- Prioritized list of most impactful inconsistencies

**Dependencies**: None (can run in parallel with 01-01)

## Tasks

<task id="01-02-01" type="discover" wave="1">
  <description>Audit spacing and layout inconsistencies</description>
  <instructions>
1. Examine spacing patterns across key screens:
   - Game screens: `games_list_widget.dart`, `create_game_widget.dart`, `game_joined_detailed_widget.dart`, `join_game_detailed_widget.dart`
   - Social: `golfers_widget.dart`, `community_widget.dart`, `tab_friends_widget.dart`
   - Profile: `main_profile_widget.dart`, `edit_profile_widget.dart`, `profile_user_firebase_widget.dart`
   - Chat: `chat_widget.dart`, `game_chat_details_widget.dart`
   - Auth: `sign_in_widget.dart`, `sign_up_account_widget.dart`

2. For each screen, document:
   - Hardcoded spacing values (e.g., `SizedBox(height: 16)` vs `height: 20` vs `height: 24`)
   - Inconsistent padding/margin patterns
   - Layout spacing that doesn't follow design token scale
   - Screen-specific spacing that should be standardized

3. Create `.planning/phases/01-foundation-audit/spacing-inconsistencies.md` with:
   - Examples grouped by screen area
   - Common patterns (e.g., "card spacing varies between 12, 16, 20, 24")
   - File paths and approximate line numbers for each example
  </instructions>
  <rationale>Spacing inconsistencies are highly visible and impact the app's polish perception</rationale>
</task>

<task id="01-02-02" type="discover" wave="1">
  <description>Audit typography inconsistencies</description>
  <instructions>
1. Examine text styling patterns across the same key screens from 01-02-01

2. For each screen, document:
   - Inconsistent heading styles (same semantic level styled differently)
   - Body text with different sizes/weights in similar contexts
   - Label and caption text inconsistencies
   - Hardcoded text styles vs design token usage
   - Color inconsistencies for text

3. Create `.planning/phases/01-foundation-audit/typography-inconsistencies.md` with:
   - Examples of similar elements styled differently (e.g., "screen titles use fontSize 20, 22, 24 across different screens")
   - Hierarchy violations (body text larger than headings, etc.)
   - File paths and approximate line numbers
   - Screenshots or visual examples if patterns are subtle
  </instructions>
  <rationale>Typography inconsistencies hurt readability and visual hierarchy</rationale>
</task>

<task id="01-02-03" type="discover" wave="1">
  <description>Audit component usage inconsistencies</description>
  <instructions>
1. Examine how similar UI elements are implemented differently across screens:
   - Buttons: primary actions, secondary actions, text buttons, icon buttons
   - Cards: game cards, user cards, info cards
   - Input fields: text inputs, dropdowns, date pickers
   - Lists: friend lists, game lists, chat messages
   - Dialogs and bottom sheets

2. For each component type, document:
   - Where the reusable component is used vs custom implementation
   - Visual differences when similar elements should look the same
   - Inconsistent variants (e.g., some primary buttons have elevation, some don't)
   - Missing reusable component usage where it should be applied

3. Create `.planning/phases/01-foundation-audit/component-inconsistencies.md` with:
   - Side-by-side examples of the same logical element styled differently
   - File paths showing where each variant appears
   - Notes on which implementation should be the standard
  </instructions>
  <rationale>Component inconsistencies are the core focus area and most visible to users</rationale>
</task>

<task id="01-02-04" type="discover" wave="2">
  <description>Audit screen flow and navigation inconsistencies</description>
  <instructions>
1. Examine navigation patterns and screen transitions:
   - How screens transition (slide, fade, instant)
   - Back button behavior and placement
   - Bottom navigation consistency
   - Modal presentation styles (bottom sheet vs dialog vs full screen)
   - Loading states and empty states

2. Document:
   - Inconsistent transition types for similar navigation actions
   - Different loading indicator patterns
   - Inconsistent empty state messaging/styling
   - Navigation that feels abrupt or jarring

3. Add findings to `.planning/phases/01-foundation-audit/navigation-inconsistencies.md`
  </instructions>
  <rationale>Smooth, predictable navigation is key to professional app feel</rationale>
</task>

<task id="01-02-05" type="document" wave="3">
  <description>Create prioritized inconsistency report</description>
  <instructions>
1. Synthesize findings from all inconsistency audits (spacing, typography, components, navigation)

2. Create `.planning/phases/01-foundation-audit/inconsistency-priority-report.md` with:

   **High Priority (most visible, biggest impact):**
   - List top 5-7 inconsistencies that are most noticeable
   - Example: "Primary action buttons have 3 different styles across game and profile screens"

   **Medium Priority (noticeable but less critical):**
   - Inconsistencies that affect polish but aren't immediately jarring

   **Low Priority (refinements):**
   - Minor inconsistencies that can be addressed later

   **Quantitative Summary:**
   - Total screens audited
   - Total inconsistencies found
   - Breakdown by category (spacing, typography, components, navigation)

3. For each priority item, include:
   - Clear description of the inconsistency
   - File paths where it occurs
   - Suggested standardization approach
   - Visual impact assessment
  </instructions>
  <depends_on>01-02-01,01-02-02,01-02-03,01-02-04</depends_on>
  <rationale>Prioritization ensures we fix the most impactful issues first in subsequent phases</rationale>
  <checkpoint>Pre-commit verification of documentation quality</checkpoint>
</task>

## Checkpoints

### Mid-execution (after task 01-02-04)
**Purpose**: Verify inconsistency audit is thorough and representative

**Check**:
- All major screen categories covered (games, social, profile, chat, auth)
- Each inconsistency type documented (spacing, typography, components, navigation)
- Examples are specific with file paths
- Findings include both "what's wrong" and "what should be standard"

**If issues found**: Expand audit to cover missed screen categories or inconsistency types

### Pre-commit (after task 01-02-05)
**Purpose**: Ensure priority report is actionable for Phase 2

**Check**:
- Priority report clearly ranks issues by impact
- Each priority item has specific examples and file paths
- Suggested approaches are realistic and achievable
- Report provides clear direction for standardization work

**If issues found**: Refine priority assessments and suggested approaches

## Notes

- This is discovery work - no code changes
- Be thorough but don't aim for perfection - sample representative screens
- Focus on patterns, not every single instance
- Visual inconsistencies matter most (what users see)
- Document current state objectively
- Screenshots or visual examples help communicate subtle issues
- All findings inform Phases 2-5 standardization work
