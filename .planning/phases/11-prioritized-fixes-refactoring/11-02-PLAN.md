  <action>
    Add notifyListeners() after cache updates to trigger widget rebuilds:

    1. **After cache writes**:
       - _chatCache[chatId] = chat; notifyListeners();
       - _messagesCache[chatId] = messages; notifyListeners();
       - Pattern: Store → Timestamp → Notify

    2. **After mutation operations**:
       - sendMessage: After sending → Update cache → notifyListeners()
       - deleteMessage: After deleting → Invalidate cache → notifyListeners()
       - updateMessage: After updating → Update cache → notifyListeners()

    3. **Dispose safety** (from Plan 11-01 patterns):
       - if (!mounted) return; before notifyListeners() in async contexts
       - Pattern from UserProvider: try { await operation(); } finally { if (mounted) notifyListeners(); }

    4. **Debounce rapid calls** (from Phase 10-01 audit recommendation):
       - If multiple cache updates in quick succession, batch notifyListeners()
       - Timer? _notifyTimer; // Debounce timer
       - void _scheduleNotify() { _notifyTimer?.cancel(); _notifyTimer = Timer(Duration(milliseconds: 50), notifyListeners); }

    Reference UserProvider patterns:
    - After queryUsersRecord: _cacheUser(user); notifyListeners();
    - After refreshCurrentUser: _currentUser = user; notifyListeners();
    - In dispose: Cancel timers before super.dispose()
