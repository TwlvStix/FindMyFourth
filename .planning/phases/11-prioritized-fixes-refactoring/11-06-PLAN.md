    Replace non-atomic game join with Firestore transaction:

    **Current race condition** (Phase 10-03 audit A-RACE-003):
    - Widget reads game capacity: 3/4 slots
    - Two users click Join simultaneously
    - Both read 3/4, both update to 4/4
    - Result: 5/4 players (overbooking)

    **Fix in GameService.joinGame**:
    ```dart
    static Future<void> joinGame(String gameId, String userId) async {
      try {
        await FirebaseFirestore.instance.runTransaction((transaction) async {
          // 1. Read game document
          final gameRef = FirebaseFirestore.instance.collection('games').doc(gameId);
          final gameDoc = await transaction.get(gameRef);

          if (!gameDoc.exists) {
            throw GameOperationException('Game not found', code: 'game-not-found');
          }

          final game = GamesRecord.fromSnapshot(gameDoc);
          final currentPlayers = game.joinedPlayers?.length ?? 0;
          final maxPlayers = game.maxPlayers ?? 4;

          // 2. Check capacity atomically
          if (currentPlayers >= maxPlayers) {
            throw GameOperationException('Game is full', code: 'game-full');
          }

          // 3. Check not already joined
          if (game.joinedPlayers?.contains(userId) ?? false) {
            throw GameOperationException('Already joined this game', code: 'already-joined');
          }

          // 4. Atomic update - only if checks pass
          transaction.update(gameRef, {
            'joined_players': FieldValue.arrayUnion([userId]),
            'updated_at': FieldValue.serverTimestamp(),
          });
        });

        debugPrint('GameService.joinGame: User $userId joined game $gameId');
      } on FirebaseException catch (e) {
        debugPrint('GameService.joinGame error: ${e.code} - ${e.message}');
        if (e.code == 'aborted') {
          throw GameOperationException('Game capacity changed, please try again', code: 'transaction-conflict');
        }
        rethrow;
      }
    }
    ```

    **Widget error handling** (join_game_detailed_widget.dart):
    - Catch GameOperationException with code 'game-full'
    - Show SnackBar: "This game is now full"
    - Catch code 'already-joined': "You've already joined this game"
    - Catch code 'transaction-conflict': "Game updated by another user, please refresh"

    **DO NOT change**:
    - UI layout or join button
    - Loading state management
    - Success handling (navigation after join)

    Replace non-atomic chat send with transaction for last_message update:

    **Current race condition** (Phase 10-03 audit A-RACE-004):
    - User A sends message at T0
    - User B sends message at T0+100ms
    - Both update chat.last_message field
    - Result: Only B's message recorded in last_message (A's lost)

    **Fix in ChatService** (likely sendMessage or similar):
    ```dart
    static Future<void> sendMessage({
      required String chatId,
      required String senderId,
      required String text,
    }) async {
      try {
        final messageRef = FirebaseFirestore.instance
          .collection('game_chats')
          .doc(chatId)
          .collection('messages')
          .doc(); // Auto-generated ID

        await FirebaseFirestore.instance.runTransaction((transaction) async {
          // 1. Create message document
          transaction.set(messageRef, {
            'sender': senderId,
            'text': text,
            'timestamp': FieldValue.serverTimestamp(),
            'chat_id': chatId,
          });

          // 2. Update parent chat's last_message atomically
          final chatRef = FirebaseFirestore.instance.collection('game_chats').doc(chatId);
          transaction.update(chatRef, {
            'last_message': text,
            'last_message_time': FieldValue.serverTimestamp(),
            'last_sender_id': senderId,
          });
        });

        debugPrint('ChatService.sendMessage: Message sent to chat $chatId');
      } on FirebaseException catch (e) {
        debugPrint('ChatService.sendMessage error: ${e.code} - ${e.message}');
        rethrow;
      }
    }
    ```

    **Key insight**: Transaction ensures last_message always reflects the message with highest timestamp, even with concurrent sends.

    **Widget changes**: Minimal - error handling only (transaction failures are rare, retryable)
